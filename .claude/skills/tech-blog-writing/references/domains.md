# 분야별 근거 체크리스트

유형 템플릿에 덧붙이는 보조 체크리스트다. CP1(증거 수집)에서 무엇을 모아야 하는지, CP4(검토)에서 무엇이 빠졌는지 확인할 때 쓴다.
해당하지 않는 항목은 건너뛴다. 해당하는데 자료가 없으면 본문에 "확인하지 못함"으로 밝힌다.

## AI/ML/LLM

분석 샘플 중 **버전과 재현 정보가 가장 자주 빠진 분야**다. 가장 빨리 낡는 분야이기도 하다.

- [ ] **모델:** 이름, 크기, revision이나 커밋 해시, 정밀도(bf16, fp8, AWQ 등)
- [ ] **API 모델이면:** 모델 ID 전체(날짜 접미사 포함), 호출 날짜, 주요 파라미터(temperature, max tokens)
- [ ] **서빙·학습 프레임워크 버전:** vLLM, transformers, PyTorch, CUDA 등
- [ ] **하드웨어:** GPU 종류와 장수, 메모리
- [ ] **평가:** 평가셋 이름과 문항 수, 평가 도구와 버전, 샘플링 파라미터, 반복 횟수
- [ ] **속도와 품질을 짝지어 보고:** 처리량만이 아니라 정확도 변화도 함께
- [ ] **프롬프트:** 결과에 영향을 준 프롬프트는 전문을 텍스트로
- [ ] **시점 표기:** 결과가 성립하는 버전 경계. 날짜는 API 모델·가격처럼 버전으로 고정되지 않을 때만
- [ ] **논문 인용:** 원문 링크, 표본 크기, 원문이 밝힌 한계
- [ ] **가격·한도:** 공식 페이지 링크와 확인 날짜. 환산했으면 환산식

## 백엔드/DB

메커니즘 확인에는 강하지만 **환경 정보가 자주 빠진 분야**다.

- [ ] **버전:** DB 엔진과 버전, 드라이버, 런타임(JDK 벤더와 빌드), 프레임워크
- [ ] **실행 계획:** EXPLAIN / EXPLAIN ANALYZE 원문 (type, rows, loops, 실제 시간)
- [ ] **풀과 스레드 상태:** 커넥션 풀의 total, active, idle, waiting. 필요하면 스레드 덤프 발췌
- [ ] **부하 조건:** TPS, 동시성, 데이터 규모, 네트워크 조건(loopback 여부 등)
- [ ] **설정값:** 문제와 관련된 설정을 기본값과 함께 (예: 타임아웃, 격리 수준)
- [ ] **재현 테스트 코드나 저장소**
- [ ] **1차 근거:** 공식 매뉴얼, JEP, 소스 코드의 줄 링크, 라이브러리 PR

## 시스템 인프라

**원시 출력으로 증명하는 관습이 가장 강한 분야**다.

- [ ] **환경 표:** 쿠버네티스 버전, CNI, 컨테이너 런타임, 드라이버, Helm 차트 버전, 노드 이미지, 클라우드 리전
- [ ] **원시 출력:** kubectl과 CLI 출력, 저널 로그 타임스탬프를 텍스트로
- [ ] **업스트림 대조:** 관련 이슈와 PR 번호, 수정이 포함된 버전
- [ ] **토폴로지 다이어그램:** 요청 경로, 장애 연쇄
- [ ] **타임라인:** 장애라면 탐지, 완화, 복구 시각
- [ ] **재발 방지:** IaC 반영, 알림 추가
- [ ] **설정 YAML이 중심인 글도 제품 버전을 적는다**
- [ ] **민감 정보 제거:** 계정 ID, 내부 도메인, IP, 토큰을 가렸다

## 기타 분야

- **FE:** 커밋 해시, 빌드 산출물 분석, 브라우저와 버전, 네트워크·CPU 스로틀 조건, 중앙값과 IQR, 스펙과 MDN 링크
- **NET:** RFC 원문과 절 번호, tcpdump나 Wireshark 출력, 실제 헤더 덤프
- **CS:** 교과서나 언어 명세의 절, 손계산 예제
