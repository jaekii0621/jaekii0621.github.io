# 링크 스크랩 추가

스크랩 카드는 대표 이미지, 출처·날짜, 제목, 요약, 💬 코멘트로 이루어진다. 카드의 가치는 **원문을 대신 읽어 준 요약**과 **사용자가 이 글을 고른 이유(코멘트)**에서 나온다. 이 스킬은 요약은 대신 쓰지만, 코멘트는 사용자의 의견이므로 지어내지 않는다.

## 절대 규칙

1. **코멘트를 지어내지 않는다.** 사용자가 말한 이유만 쓴다. 후보를 제안할 수는 있지만 사용자가 고르거나 고쳐야 저장한다. 사용자가 비워 두라고 하면 `comment: ""`로 둔다.
2. **요약은 원문을 실제로 읽고 쓴다.** 원문을 가져오지 못하면(유료 구독, 로그인 필요, 차단) 그 사실을 사용자에게 알리고, og:description만 근거로 썼다고 밝힌다. 원문에 없는 수치나 주장을 넣지 않는다.
3. **원문 문장을 길게 옮기지 않는다.** 요약은 자기 말로 다시 쓴다. 따옴표 인용은 한 군데, 15단어 이하까지만 허용한다.
4. **사용자 확인 없이 저장하거나 커밋하지 않는다.** 아래 "확인" 단계에서 승인을 받은 뒤 파일을 확정한다.

## 저장 형식

한 건당 YAML 파일 하나. 스키마는 `src/content.config.ts`의 `links` 컬렉션이 기준이다.

```yaml
url: "https://example.com/post"        # 리다이렉트를 따라간 최종 URL
title: "원문 제목"                       # 원문 언어 그대로
source: "사이트 이름"                    # 사람이 읽는 이름 (GitHub, Anthropic 등)
image: "../../assets/links/<파일명>.webp" # 카드 썸네일. 없으면 줄을 뺀다
imageSource: "https://example.com/og.png" # 썸네일을 만든 원본 og:image
summary: "한국어 요약 60자 이내 1~2문장."
comment: "왜 골랐는지 한 줄"              # 사용자가 준 것만
tags: ["ai", "agent"]
date: 2026-10-29T15:20:00+09:00         # 스크랩한 시각, 한국 시간 (원문 발행일 아님). 목록 정렬 기준
```

파일 이름은 `날짜-도메인-경로끝.yaml`이며 `pnpm scrap`이 정해 준다. 썸네일은 같은 이름의 `src/assets/links/<파일명>.webp`다.

## 작업 순서

### 1. 중복 확인

```bash
grep -rl "<URL의 핵심 부분>" src/content/links/
```

이미 있으면 새로 만들지 않고 기존 파일을 보여 주며 수정할지 묻는다. URL은 `www.`, 끝의 `/`, `utm_*` 같은 추적 파라미터를 빼고 비교한다.

### 2. 초안 생성

추적 파라미터(`utm_*`, `fbclid`, `gclid` 등)를 지운 URL로 실행한다.

```bash
pnpm scrap <url> [태그 ...]
```

스크립트는 og 메타데이터로 `url`, `title`, `source`, `imageSource`, `summary`(임시로 og:description), `date`를 채운다. og:image는 내려받아 카드 비율(800×419) WebP 썸네일로 줄여 `src/assets/links/`에 저장하고 `image`에 경로를 적는다. 원본 용량과 썸네일 용량이 출력된다. 실패하면(4xx/5xx, 차단) 에러를 사용자에게 알리고, 사용자가 원하면 같은 형식으로 파일을 직접 만든다.

### 3. 원문 읽기

WebFetch로 원문을 읽는다. 유튜브·PDF·트윗처럼 본문을 못 가져오는 경우는 가져올 수 있는 만큼만 읽고, 무엇을 근거로 요약했는지 사용자에게 밝힌다.

### 4. 항목 다듬기

| 항목 | 다듬는 법 |
|---|---|
| `title` | 사이트 이름 접두사·접미사를 뗀다 (`GitHub - `, ` \| Medium`, ` - 회사 블로그`). 원문 언어를 유지하고 번역하지 않는다. |
| `source` | 도메인 대신 사람이 읽는 이름으로 쓴다 (`anthropic.com` → `Anthropic`). 개인 블로그는 `저자 이름 blog`. |
| `summary` | 한국어 1~2문장, 60자 이내. "~다"체. 핵심 주장이나 결과 하나에 집중하고, 있으면 가장 인상적인 수치나 사례 하나를 붙인다. 카드는 3줄(좁은 카드에서 약 65자)까지 보이므로 첫 문장만 읽어도 무슨 글인지 알게 쓴다. |
| `image` | 스크립트 출력에서 썸네일이 만들어졌는지 확인하고, 생성된 WebP를 Read로 열어 본다. 사이트 로고만 있는 기본 이미지이거나 자르면서 핵심이 잘렸으면 사용자에게 알린다. 쓰지 않기로 하면 `image` 줄과 WebP 파일을 지운다(카드가 도메인 이름으로 대체된다). 썸네일 생성이 실패했으면 이유를 알린다. 썸네일을 다시 만들려면 `pnpm scrap --thumb <yaml 파일>`을 쓴다. |
| `tags` | 먼저 기존 태그를 확인해 같은 뜻이면 기존 것을 쓴다. 영어 소문자, 단어는 `-`로 잇는다. 1~3개. |

기존 태그 확인:

```bash
grep -h "^tags:" src/content/links/*.yaml | sort | uniq -c | sort -rn
```

### 5. 확인 (사용자 승인)

다음을 한 번에 보여 주고 멈춘다.

```
📎 <title>
   <source> · <date> · 태그: <tags>
   썸네일: 있음 (원본 → 썸네일 용량) / 없음(이유)

   요약: <summary>

   코멘트: <사용자가 준 것, 없으면 "비어 있음">
```

- 코멘트가 없으면 "이 글을 왜 골랐는지 한 줄 알려 주세요"라고 묻는다. 원하면 원문 내용에 근거한 후보 2개를 제안하되, `(제안)`이라고 표시한다.
- 사용자가 고친 내용을 반영해 파일을 확정한다.

### 6. 검증

```bash
pnpm build
```

스키마 오류(잘못된 URL, 빠진 필드)가 나면 고친다. 개발 서버가 떠 있으면 홈과 `/links`에서 카드가 보이는지 확인할 수 있다. 개발 서버는 `astro dev --background`로 띄우고, 새 파일이 반영되지 않으면 `astro dev stop` 후 다시 띄운다.

### 7. 커밋 (묻고 나서)

사용자가 원할 때만 커밋하고, 여러 건이면 한 커밋으로 묶는다.

```
Add scrap: <title>
```

여러 건이면 `Add N scraps` 제목 아래 `- <title>` 목록을 쓴다.

## 여러 링크를 한꺼번에 받았을 때

1~4단계를 링크마다 처리한 뒤, 5단계 확인은 모아서 한 번에 보여 준다. 코멘트는 링크마다 따로 받는다.

## 하지 않는 것

- 원본 이미지를 그대로 저장하지 않는다. 카드용 썸네일만 저장하고, 원본은 `imageSource`에 URL로만 남긴다. 원작자가 내려 달라고 하면 썸네일을 지운다.
- 원문 발행일로 `date`를 바꾸지 않는다. `date`는 스크랩한 시각이다. 시각을 지우면 같은 날 스크랩끼리 순서가 정해지지 않으므로 날짜만 남기지 않는다.
- 샘플 스크랩(코멘트에 `(샘플)`이 있는 파일)은 사용자가 요청할 때만 지운다.
