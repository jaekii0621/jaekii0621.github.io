### 19. web-vitals는 언제 핵심 웹 지표를 보고하는가 (yceffort)
- **유형/분야:** FE 확정. 유형은 **T/E 혼합**으로 봅니다. 이상 관측으로 시작하지만 본문 대부분은 라이브러리 소스를 해설합니다.
- **도입:** 직접 만든 재현 실험의 이상 결과로 시작합니다. 10회 클릭했는데 INP가 0회 보고됐고, 이탈 시점을 늦추니 10회 모두 보고됐습니다. 이어서 이 차이가 왜 중요한지를 설명합니다. "콜백이 안 불린 방문은 수집 데이터에서 사라진다"는 점입니다.
- **구조:** 이상 관측 → 기준 버전·측정 환경 박스 → 결론 표(지표별 보고 시점과 누락 조건) → 소스 경로 순 해설(observe → bindReporter → 가시성 감시 → 지표별 report 호출 지점) → idle까지 미루는 1초 → 그 1초 안에 떠나면 누락 → bfcache → 정리(누락을 구별하는 조건, 한계, 아직 배포되지 않은 수정).
- **근거:** 매우 강합니다. 태그·커밋 해시·배포일을 고정하고, 브라우저와 Playwright 버전, 실제 Chrome에서 한 교차 측정, 측정 코드 저장소 경로, 줄 번호가 붙은 소스 인용, 이슈·PR 번호, 조건별 측정 표, 각주 16개를 갖췄습니다. 빌드 산출물이 npm 배포본과 바이트 단위로 같다는 것까지 확인했습니다.
- **불확실성:** 측정 방법의 선택 이유를 적습니다(sessionStorage 대신 sendBeacon을 쓴 이유). 기준 버전 이후 main에 들어온 수정은 따로 표시해 경계를 그었습니다.
- **마무리:** 요약, 측정 범위의 한계, 미배포 수정이 미칠 영향.
- **형식:** 결론 표를 앞에 두고, 코드 블록에는 버전과 경로 주석을 달고, 시퀀스 다이어그램을 씁니다.

- **기법:** ① 기준 버전과 커밋을 인용 블록 하나에 모아 고정하고, 그 뒤의 변경은 "이후"로 따로 표기합니다. ② 결론 표를 글 앞쪽에 두고 본문은 그 표를 증명하는 순서로 씁니다.

### 23. turbopack에서 싱글톤이 두 개가 됐다 (yceffort)

- **마무리:** 해법 3안과 교훈을 단락으로 쓰고 참고 링크로 끝냅니다.
- **형식:** 증상별 상태 표, 접근 경로 표, 버전 포함 표, ON/OFF 대조 표. 코드 블록이 많습니다.
- **문체:** 반말 평서체에 1인칭 반성이 들어갑니다. 장문입니다.

- **유형/분야:** BE 확정. 유형은 **설계·구현기(시리즈 3편)로 재분류**하고 T 요소가 섞인 것으로 봅니다. 장애를 겪은 것이 아니라 예상된 한계를 해소하는 글이고, 그 과정에서 버그 두 개를 잡았습니다.

- **문체:** 존댓말이고 1인칭입니다. 약 1만 자입니다.
- **기법:** 앞에서 복선으로 깔아둔 결함을 뒤에서 회수해 실수를 서사의 일부로 씁니다. 실패를 "감지 방법"으로 분류하고 분류마다 대응 도구를 하나씩 둡니다.

### 2.3 분야별 근거 관습
- **FE (19, 23):** 근거 밀도가 가장 높습니다. 패키지 버전과 **커밋 해시**를 고정하고, 브라우저와 런타임 버전, 측정 하네스와 저장소, 빌드 산출물 직접 분석(grep, 번들 발췌), `gh api`로 확인한 수정 포함 버전, 단일 변수 ON/OFF 대조 표를 씁니다. 경로가 붙은 소스 인용이 기본입니다.
- **BE (26, 34, 37, 87~89, 109~115, 118, 119):** 실행계획(EXPLAIN 또는 EXPLAIN ANALYZE의 type, rows, loops), 커넥션 풀 로그(total/active/idle/waiting), 측정치 ms 대조, 라이브러리 소스나 PR 논의, 재현 테스트 코드가 주된 근거입니다. 공식 매뉴얼은 직접 인용합니다. **버전을 빼먹는 글이 많습니다**(113, 109, 110, 115, 87). 저년차 글은 감정 서술과 비유로 이해를 돕는 경향이 있습니다(110 은행 창구, 113).
- **INF (106~108, 122, 123):** 환경 표(배포 도구, k8s, 런타임, 드라이버, 차트 버전), kubectl과 CLI 출력, 저널 타임스탬프, 업스트림 이슈 번호, 공식 트러블슈팅 문서, Helm revision을 씁니다. 토폴로지와 연쇄를 보여주는 mermaid 다이어그램을 많이 씁니다. 전후 메트릭은 대시보드 캡처로 보여줍니다(122). 재발 방지를 IaC 승격이나 알림 추가로 끝내는 관습이 있습니다(106, 107).
- **AI (97, 1편뿐):** 정상과 비정상 출력 텍스트를 대조하고, GPU 종류를 밝히고, GitHub 이슈와 옵션 문서를 인용합니다. 버전과 재현 스크립트가 없어 근거가 가장 약했습니다. 표본이 1편이라 일반화할 수 없습니다.

### 2.4 신뢰를 높이는 기법
1. **기준 버전과 환경을 한 블록에 고정합니다.** 이후의 변경은 따로 표시합니다(19, 23, 107, 112).
2. **확정, 추정, 미확정을 문장 단위로 분리합니다.** "여기까지가 직접 확인한 사실"(23), 로그가 없어 확정하지 못한 사건을 분리(107).
3. **틀린 가설과 헛걸음을 그 자리에서 기록하고 기각 근거를 붙입니다**(23, 107, 110, 112, 113).
4. **단일 변수 대조 실험을 합니다.** 옵션 ON/OFF, 대조군 서비스, 같은 프롬프트(23, 115, 97, 88).
5. **깨뜨린 조작과 같은 조작으로 수정을 검증합니다.** red/green 기록, 실패하는 테스트를 먼저 작성(107, 110, 118).
6. **업스트림 대조:** 이슈와 PR 번호를 찾고, 수정이 들어간 버전을 커밋과 태그로 확인합니다(23, 106, 108).
7. **남은 나쁜 수치와 한계를 결과 표에 그대로 둡니다**(114, 118).
8. **응급조치와 영구 조치를 구분해 재발 경로를 닫습니다.** 핫픽스를 IaC로 승격, 알림 추가(106, 107, 114).
9. **분량을 깊이에 비례해 배분합니다.** 사소한 triage는 압축하고 핵심 한 겹에 집중합니다(106).

### 2.5 신뢰를 떨어뜨리는 안티패턴
- **버전과 환경 누락:** 재현과 적용 가능성을 판단할 수 없습니다(97, 109, 110, 113, 115, 123).
- **원인을 "조사 결과"로만 제시:** 자기 환경에서 그 기전이 작동했다는 직접 증거가 없습니다(122의 conntrack, 123).
- **해결안을 적용한 결과가 없음:** 제안만 하고 끝납니다(115, 123).
- **핵심 근거가 이미지에만 있음:** 로그, 메트릭, 소스를 텍스트로 검색하거나 인용할 수 없습니다(37, 87, 122).
- **배경 설명이 원인 서술을 압도:** 증상과 맥락이 늦게 나와서 트러블슈팅인지 해설인지 흐려집니다(34).
- **일반론 서론:** "K8s를 운영하다 보면…"처럼 증상과 무관하게 시작합니다(122, 123, 26).
- **감정 서술 과다:** 근거 밀도를 희석합니다(113의 반복된 "이게 웬걸", 97의 ㅋㅋ). 짧은 메모라면 허용되는 수준입니다.

### 2.6 스킬 체크리스트 후보
1. **도입 세 문단 안에 관측된 증상을 구체적으로 쓴다.** 로그 한 줄, 수치 대조, 알림 문구 중 하나를 쓰고 일반론 서론은 피한다. (23, 97, 106, 107, 112, 113 / 반례 122, 123)
2. **환경과 버전을 블록이나 표 하나로 고정한다.** 버전, 런타임, 측정 도구, 일반화 고지를 넣고, 기준 이후 변경은 따로 표시한다. (19, 23, 107, 112 / 누락 97, 109, 110, 113)
3. **원인을 단정하기 전에 가설과 기각 근거를 남긴다.** 틀린 가설은 지우지 말고 "왜 틀렸나"를 한 줄 붙인다. (23, 107, 110, 112, 113)
4. **확정, 추정, 미확정을 구분해 표기한다.** "직접 확인한 것은 여기까지", "로그가 없어 확정하지 못함" 같은 문장을 쓴다. (23, 107, 97, 118)
5. **원인은 단일 변수 실험이나 재현으로 증명한다.** 조건 목록, 실패하는 테스트, ON/OFF 대조 중 하나를 쓴다. 문서를 인용하는 것만으로 끝내지 않는다. (23, 107, 110, 113, 115, 123 / 약점 122)
6. **수정은 문제를 일으킨 것과 같은 조작이나 측정으로 검증하고, 전후 수치를 표로 낸다.** 남은 나쁜 수치도 숨기지 않는다. (107, 109, 112, 114, 122, 119)
